A Claude Code hook that blocks force-push, rm -rf and curl | sh

A line in CLAUDE.md saying "never force-push" is a request. A hook is a guarantee. Claude Code runs PreToolUse hooks before every tool call, and a hook that blocks the call stops the command before it runs. This guide shows a complete, copyable guard script for the commands that cause the worst days: force pushes, skipped checks, rm -rf on a home directory, and curl | sh. Every case below was run against the script before publishing.

How a blocking hook works

The Claude Code hooks reference describes the lifecycle: PreToolUse fires "before a tool call executes" and "can block it". Claude Code passes the tool call to your command as JSON on stdin; for the Bash tool the command text is at tool_input.command. If your script exits with status 2 it is a blocking error: the call does not run, and what you print to stderr is sent back to the model so it can choose another approach. Exit 0 lets the call through.

The script

Save this as .claude/hooks/block_dangerous.py in your project. It uses only the Python standard library and makes no network calls.

#!/usr/bin/env python3
import json, re, sys

BLOCKED = [
    (r"git\s+push\b.*(\s-f\b|--force(?!-with-lease))", "force-pushing rewrites shared history"),
    (r"git\s+(commit|push|merge)\b.*--no-verify", "--no-verify skips your checks"),
    (r"\brm\s+-\S*r\S*\s+(/|~/?|\$HOME/?)(\s|$)", "this deletes a root or home directory"),
    (r"(curl|wget)\b[^|;&]*\|\s*(sudo\s+)?(ba|z)?sh\b", "piping a download into a shell runs unreviewed code"),
]

event = json.load(sys.stdin)
command = (event.get("tool_input") or {}).get("command", "")
for pattern, why in BLOCKED:
    if re.search(pattern, command):
        print(f"Blocked: {why}. Ask the user to run it themselves.", file=sys.stderr)
        sys.exit(2)
sys.exit(0)

Register it

Add this to .claude/settings.json (project-wide, committed) or ~/.claude/settings.json (every project):

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block_dangerous.py" }
        ]
      }
    ]
  }
}

Test it before you trust it

Pipe a fake event into the script and check the exit status. For example echo '{"tool_input":{"command":"git push origin main --force"}}' | python3 .claude/hooks/block_dangerous.py; echo $? prints the reason on stderr and then 2. Results from running the script above:

CommandExit
git push origin main --force2 (blocked)
git push --force-with-lease origin f0 (allowed)
git commit -m x --no-verify2 (blocked)
rm -rf ~/2 (blocked)
rm -rf build0 (allowed)
curl -s https://x.example/i.sh | sh2 (blocked)
ls -la0 (allowed)

Note that --force-with-lease is deliberately allowed: it refuses to overwrite commits you have not seen, which makes it the safer form.

Limits, honestly

  • Pattern matching on a command string is a safety net, not a sandbox. A determined sequence of shell tricks can get past any regular expression. The hook is there to stop the common accident.
  • Keep the list short and specific. A guard that blocks ordinary commands gets disabled, and then protects nothing.
  • Edits count too. Add an Edit|Write matcher and block paths that should only change through tooling, such as generated schema files or committed database migrations.
