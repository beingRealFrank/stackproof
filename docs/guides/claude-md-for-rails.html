A CLAUDE.md for Rails projects that matches your repo

A templated CLAUDE.md for Rails usually says bundle exec rspec and rubocop, and the repo may do neither. The agent then runs the wrong command or guesses at the setup. This guide writes a CLAUDE.md by reading the repository first, using the public mastodon/mastodon repository at commit 5b74d40 as the example.

Step 1: read the real versions

cat .ruby-version
grep -n "gem 'rails'" Gemfile

Mastodon's .ruby-version is 4.0.9 and its Gemfile pins rails ~> 8.1.0. Write what you find, not what you remember: the Rails version decides which APIs and defaults exist.

Step 2: find the test command CI actually runs

ls .github/workflows
grep -n "rspec\|flatware" .github/workflows/test-ruby.yml

Mastodon's Ruby test workflow loads the schema with bin/rails db:setup and runs bin/flatware rspec (a parallel runner), with RAILS_ENV=test and Postgres and Redis services. Single files can use bin/rspec, which the same workflow uses for tagged specs (bin/rspec --tag search). A generic bundle exec rspec line would miss the binstubs and the services.

Step 3: find the linters

grep -n "rubocop\|brakeman" .github/workflows/lint-ruby.yml
grep -n '"lint\|"test' package.json

The lint workflow runs bin/rubocop and bin/brakeman. The JavaScript side uses yarn (packageManager is yarn@4.18.1), with yarn lint and yarn test. CONTRIBUTING.md lists rspec, vitest, rubocop, eslint and i18n-tasks as the required checks.

Step 3b: record the setup commands

docs/DEVELOPMENT.md says to run RAILS_ENV=development bin/setup and then bin/dev, which starts the services through overmind or foreman.

Step 4: write the Never section

  • Never edit a committed migration in db/migrate or hand-edit db/schema.rb; add a migration and let Rails regenerate the schema (see stopping an agent editing schema.rb).
  • Never read or edit .env* files or commit credentials; Mastodon ships .env.production.sample as the safe reference.
  • Never run bin/rails db:drop or db:reset against anything but the test database.

The result

## Project facts
- Ruby 4.0.9 (.ruby-version); Rails 8.1 (Gemfile); Postgres + Redis.
- Frontend: yarn 4 (package.json). Tests: rspec, vitest.

## Commands
- Setup: RAILS_ENV=development bin/setup
- Run: bin/dev
- Ruby tests: bin/flatware rspec   One file: bin/rspec spec/path_spec.rb
- JS tests: yarn test
- Lint: bin/rubocop && bin/brakeman && yarn lint

## Never
- Never edit committed migrations or hand-edit db/schema.rb.
- Never touch .env files; never commit secrets.
- Never run db:drop or db:reset outside the test database.

Every line has a source you can point to. Delete any line you cannot source; a shorter file of true statements beats a long one the agent has to second-guess. If a CLAUDE.md already exists, add a marked section rather than rewriting it. Read a project's contribution policy before sending it anything: Mastodon has an AI contribution policy that you should respect.
